# Architecture

The game is split into two layers that only talk through the contract in this
file. The **sim** decides what happens; the **visuals** decide what it looks
like. Neither side imports the other's internals.

```
input (keyboard / PS5) ──► sim (fixed 240 Hz step, Rapier) ──► SimState + events ──► visuals (Three.js render, OSD, effects)
```

## Ownership

| Path            | Owner        | Contents |
|-----------------|--------------|----------|
| `src/sim/`      | game systems | flight model, physics world, level data, combat, AI, missions, battery, signal |
| `src/input/`    | game systems | keyboard + gamepad → `Controls` |
| `src/debug/`    | game systems | throwaway box renderer used to develop the sim |
| `src/visuals/`  | visuals      | everything that is drawn: scene, models, terrain mesh, lighting, effects, OSD look, video-feed shader |
| `src/main.js`   | shared       | boot + game loop. Change only with a note to the other thread |
| `ARCHITECTURE.md` | shared     | this contract. Additive changes are fine; breaking changes need agreement |

`src/visuals/index.js` starts as a stub that re-exports the debug renderer.
The visuals thread replaces it with the real implementation.

## Conventions

- Units: metres, seconds, kilograms, radians inside the sim (degrees only where a field name says `Deg`).
- Axes: Three.js convention, right-handed, **+Y up**. A body's forward is **−Z**, right is **+X**.
- Vectors are plain arrays `[x, y, z]`, quaternions `[x, y, z, w]`, so you can
  `vec.fromArray(a)` / `quat.fromArray(q)`.
- State objects are **reused between frames** (no per-frame allocation). Copy
  anything you need to keep.

## Visuals API (implemented in `src/visuals/index.js`)

```js
export function createVisuals({ canvas, uiRoot, level }) {
  return {
    update(state, events, dt), // once per animation frame, after the sim stepped
    resize(width, height),     // CSS pixels; visuals handles devicePixelRatio
    dispose(),
  };
}
```

- `canvas`: the `<canvas id="game">`. Visuals owns the `WebGLRenderer`.
- `uiRoot`: a full-screen `<div>` above the canvas for the OSD / DOM overlays.
- `level`: static `Level` data (below), given once.
- `state`: the current `SimState` (below).
- `events`: array of `SimEvent`s that happened since the last `update` (may be empty).
- `dt`: real seconds since last frame (for animation only; sim time is `state.time`).

The visuals must render the camera exactly at `state.camera` (they may add
shake / effects on top) because the camera angle is a gameplay setting.

## Level (static, given once)

```js
Level = {
  name: string,
  seed: number,
  terrain: {
    size: number,          // world width = depth in metres, centred on origin
    segments: number,      // grid cells per side
    heights: Float32Array, // (segments+1)^2, row-major: index = iz*(segments+1) + ix
                           // vertex x = -size/2 + ix*size/segments, z likewise
    heightAt(x, z): number // bilinear lookup (same surface the physics collides with)
  },
  objects: [               // static colliders; visuals draws something that fills the same volume
    { id, kind: 'building', position:[x,y,z] /* base centre on ground */, rotationY, size:[w,h,d] },
    { id, kind: 'tree',     position:[x,y,z] /* trunk base */, height, radius /* canopy radius */ },
  ],
  spawn: { position:[x,y,z], yaw },

  // Front-line scenery, shared so the sim's colliders and the visuals' meshes always match.
  // Generated by src/sim/propLayout.js (deterministic; heights come from terrain.heightAt).
  props: {
    lanes:    [[[x, z], [x, z]], ...],                  // dirt lanes, also painted into the ground
    craters:  [{ x, y, z, r, rim, water }],             // old shell craters; spoil rim ≈ 0.3 m high at radius 0.85 r. Rim has a collider
    poles:    [{ x, y, z, rotation:[rx,ry,rz], height, radius, snapped }], // from (x,y,z) up local +Y, Euler XYZ; crossarm near the top
    wires:    [{ a:[x,y,z], b:[x,y,z], sag }],          // cable between insulators, drooping `sag` m at mid-span (parabola)
    fences:   [{ a:[x,y,z], b:[x,y,z], lean, height }], // one panel between posts, 0.1 m thick
    bales:    [{ x, y, z, yaw, radius, length, wrapped }], // round bale, horizontal axis along local X
    sandbags: [{ x, y, z, yaw, roll, layer }],          // single bags ≈ 0.62 x 0.2 x 0.3 m
    // Optional fortifications (campaign map):
    trenches: [{ points: [[x, y, z], ...], width }],    // zig-zag fire / communication trench centre line; no collider (low spoil banks)
    dugouts:  [{ x, y, z, yaw, w, d, net, collapsed, player?, depth? }], // dug-in dugout: a low earth mound under a net (y = ground).
                                                        // The player's (player: true) has a room `depth` m below ground, front wall
                                                        // facing yaw (0 = −Z), and a ramp up from its rear door. Solid parts and
                                                        // the ramp rect: dugoutBoxes() / dugoutRampRect() in src/sim/propColliders.js
    masts:    [{ x, y, z, height }],                    // telescopic antenna mast (pole collider)
  },

  // Optional, campaign only:
  start?: { mode: 'foot', position: [x,y,z] /* feet */, yaw },  // begin on foot instead of in the drone
  home?: dugout,            // the dugout the player starts in (same object as in props.dugouts, player: true)
  linkOrigin?: [x,y,z],     // the video link is measured from here (mast top) instead of the launch spot
  linkRangeM?: number,      // default 800
  terrainHoles?: [[x0, z0, x1, z1], ...],  // world rects with no ground (the dugout ramp): the sim leaves them out of the
                            // ground collider, the visuals discard the terrain there. heightAt() is unchanged.
}

Level enemy defs may also carry `mission: <id>` (a target of that mission) and `hold: true` (alerted infantry go flat and shift
about their patrol line but never run off).
Infantry within 32 m of a flying drone panic instead of running: they dodge sideways across its line, hit the dirt,
throw their helmet or rifle at it (`entity_throw`) and now and then fire a burst (`entity_shot`, rarely a hit).
Hitboxes: vehicles are compound boxes per variant (HIT_SHAPES: hull, turret, gun...); infantry boxes follow posture
(standing, lying, seated).
Level enemy defs may carry `speed` (m/s along the patrol), `route: true` (one way: past the last point the unit has
escaped, status `'escaped'`, and the visuals hide it) and `waitFor: <mission id>` (parked until that mission starts).
Missions end when every target is dealt with or escaped; `outroPartial` / `outroFailed` play when some / all got away,
and the `mission` event (phase `'complete'`, or `'failed'` when any got away) carries `done, escaped`. A failed mission
restarts: its targets are put back (`entities.resetUnits`) and its `retry` lines play instead of the intro.
Level enemy defs may carry `riders: [variant, ...]`: infantry that ride on top of that vehicle (seats per
variant in RIDER_SEATS, src/sim/entities.js) until it is knocked out or stops while they are alarmed.

Everything in `props` except wires has a static collider (an explosion on one reports `surface: 'prop'`).
Wires are crashable: flying into a cable while the motors are armed tangles the props and emits
`crash` with `cause: 'wire'` (the drone drops). Poles, fences, bales and sandbags crash the drone through the
normal impact rules.
```

## SimState (per frame)

```js
SimState = {
  time: number,              // sim seconds since level start
  paused: boolean,
  mode: 'foot' | 'drone',    // 'foot' only on levels with `start`: the camera is the soldier's eyes (no feed, no OSD)
  player: null | { position:[x,y,z] /* feet */, yaw, pitch, speed, nearGoggles },
  prompt: null | 'goggles' | 'ungoggle',   // what the interact key would do now
  mission: null | {         // campaign (level.missions, src/sim/missions.js). No map markers: the briefing is the other soldier's spotter feed
    id, title, objective, phase: 'intro' | 'active' | 'outro' | 'done',
    done, total,            // targets dealt with (dead, down, or vehicle knocked out) / all
    speaker, line: string | null, lineId,   // subtitle on screen now; lineId changes with every new line (speak it once)
    cutscene: null | { position:[x,y,z], target:[x,y,z], fovDeg },  // on foot: show the spotter feed from here instead of the eyes
    bearing: null | { fromHome: { deg, m }, fromDrone: { deg, m } | null, moving: 'east' | ... | null }, // compass (0 = north = −Z) to the live targets
    spotter: { position, target, fovDeg },  // what his drone sees all the time: the TV in the dugout (copies the cutscene while there is one)
  },
  // There is no chase / third-person view: the game is FPV only.

  drone: {
    position: [x,y,z], quaternion: [x,y,z,w],
    velocity: [x,y,z], angularVelocity: [x,y,z],   // world frame
    motors: [fl, fr, rr, rl],  // normalised RPM 0..1 (prop spin speed); spin dirs: fl,rr = CW; fr,rl = CCW seen from above
    throttle: number,          // stick 0..1
    armed: boolean,
    crashed: boolean,          // props broken, needs reset
    destroyed: boolean,        // warhead went off; the drone is gone (hide it) until the next 'reset'
    flightMode: 'ACRO' | 'ANGLE',
    warhead: {
      type: 'none' | 'rpg-heat' | 'frag',
      state: 'safe' | 'armed' | 'detonated',   // safe until it is armDistanceM from launch
      massKg: number,          // carried under the frame; visuals can size the model from this
    },
  },

  camera: { position:[x,y,z], quaternion:[x,y,z,w], fovDeg /* vertical */, tiltDeg },

  hud: {                      // everything the OSD shows; visuals decides the look
    armed, flightMode,
    throttlePct,              // 0..100
    altitudeM,                // above ground under the drone
    speedKmh,
    headingDeg,               // 0 = −Z (north), clockwise
    batteryV, batteryPct, mAhUsed, currentA,
    flightTimeS,
    linkQuality,              // 0..100 (M3 makes this drop)
    warhead: 'NONE' | 'SAFE' | 'ARMED' | 'DETONATED',
    warheadArmInM: number,    // metres still to fly before the warhead arms (0 once armed)
    warnings: string[],       // e.g. 'CRASH', 'LOW BATTERY', 'THROTTLE', 'DISARMED'
  },

  link: {                     // analog video feed quality, drives the static shader
    signal: number,           // 0..1, 1 = perfect; smoothed. Drops with distance from launch (~800 m limit),
                              // when flying low (< 4 m above ground, worse the further out) and behind hills
    roll: number,             // 0..1: the picture rolls vertically (loss of sync). 0 above signal 0.6, 1 near signal 0.2.
                              // Visuals: scroll the image up/down with a sawtooth, speed and tearing scale with roll
    jamming: number,          // 0..1 (M3)
    lost: boolean,            // feed is gone (signal < 0.08 or the drone detonated): full static / no-signal
  },

  env: {
    wind: [x,y,z],            // m/s, world-frame air velocity at the drone (sway trees, drift smoke)
  },

  entities: [                 // enemy troops and vehicles. Wrecks and corpses stay in the list. Ids are never reused.
    // The list can GROW during play: a vehicle's bailing crew appear as new infantry entities
    // (variant 'crew', fromVehicle set). `targets_reset` removes them again.
    {
      id: string,               // 'e12'
      kind: 'infantry' | 'light' | 'truck' | 'apc' | 'tank',
      variant: string,          // look and stats, per kind (see the table below)
      locomotion: 'foot' | 'wheels' | 'tracks',   // for animation: legs / spinning wheels / rolling tracks
      position:[x,y,z],         // base centre on the ground (for infantry: between the feet)
      quaternion:[x,y,z,w],     // hull orientation; forward is −Z
      velocity:[x,y,z],
      size: [w,h,d],            // hull bounding box in metres (width x, height y, depth z), standing infantry
      health: number,           // 0..1 overall combat effectiveness (components + crew / body); 0 = destroyed or dead
      status: 'idle' | 'moving' | 'fleeing' | 'prone'          // acting normally
            | 'wounded' | 'crawling' | 'down'                  // infantry only, see below
            | 'disabled'                                       // vehicle: knocked out but physically intact (crew dead, immobile, no gun, abandoned...)
            | 'destroyed',                                     // vehicle: wreck (cooked off / burned out); infantry: dead
      turretYaw: number,        // radians relative to hull; tank / apc / technical. Frozen when the turret is jammed or the gunner is out
      onFire: boolean,          // burning: flames and smoke while true (= fire !== 'none' for vehicles)
      weakSpots: [{ name, position:[x,y,z], radius }],   // vehicles: the internal components, hull-local (debug marker)

      // ---- vehicles only ----------------------------------------------------------------
      kill: 'none' | 'mobility' | 'firepower' | 'mobility+firepower' | 'crew' | 'burning' | 'catastrophic',
                                // worst outcome so far. 'crew' = everybody dead or gone but it looks fine
      mobility: 'ok' | 'slow' | 'immobilized',      // engine / tracks / wheels / driver
      firepower: 'ok' | 'degraded' | 'disabled',    // gun / optics / gunner
      operational: boolean,     // can still move or fight
      crewTotal: number, crewAlive: number,         // alive and still inside
      crew: [{
        role: 'driver' | 'commander' | 'gunner' | 'loader' | 'troop',
        state: 'ok' | 'wounded' | 'dead' | 'bailed',
        visible: boolean,       // head and shoulders out of the hatch (dead + visible = slumped over it)
        position: [x,y,z],      // hull-local seat position
      }],
      hatches: { driver: boolean, commander: boolean, gunner: boolean, rear: boolean },   // open?
      bailing: boolean,         // crew are climbing out right now (a few seconds), then `abandoned`
      abandoned: boolean,
      fire: 'none' | 'engine' | 'full',
      smoke: 'none' | 'light' | 'heavy',            // from the engine deck; can happen without fire
      components: {             // 0..1 health each; `state` is 'ok' (> 0.6), 'damaged' (0.2 to 0.6) or 'destroyed' (< 0.2)
        engine, fuel,           // every vehicle
        ammo?, gun?, turret?, optics?,   // armoured vehicles / technical (turret = traverse drive: jammed when destroyed; gun = barrel)
        trackL?, trackR?,       // tracked: a destroyed track means a thrown track
        wheels?,                // wheeled
        // each: { hp: number, state: 'ok' | 'damaged' | 'destroyed', position: [x,y,z], radius: number }
      },

      // ---- infantry only ----------------------------------------------------------------
      // status: wounded = limping or holding a wound, crawling = can't stand, down = alive but incapacitated
      //         (lying, writhing, bleeding out), destroyed = dead.
      condition: 'ok' | 'wounded' | 'crawling' | 'down' | 'dead',
      wounds: { head: number, torso: number, armL: number, armR: number, legL: number, legR: number },  // 1 = unhurt .. 0 = destroyed
      mobility: number,         // 0..1 (legs)
      bleeding: boolean,
      fromVehicle?: string,     // id of the vehicle a bailed-out crewman came from (variant 'crew')
      riding: string | null,    // id of the vehicle he sits on top of (legs over the side); position = the point he sits on,
                                // quaternion = the way he faces. null once he jumps or falls off
    },
  ],
}
```

### Entity variants

`variant` picks the model and the stats. Sizes (`size`) already differ per variant, so scale models from it.

| kind | variants | notes |
|------|----------|-------|
| `infantry` | `rifleman`, `mg`, `rpg`, `officer`, `crew` | `mg` carries a belt-fed machine gun, `rpg` a rocket launcher, `officer` has a pistol / binoculars and his shout alerts the squad from further away, `crew` = a bailed-out vehicle crewman (tanker helmet and coveralls; `fromVehicle` set) |
| `light` | `uaz`, `pickup`, `technical`, `atv` | UAZ-469-style jeep, pickup truck, pickup with a mounted heavy MG (`technical` tracks the drone with its gun: `turretYaw`), quad bike with one rider (the `driver` crew seat, always visible) |
| `truck` | `ural`, `kamaz`, `fuel` | Ural-4320 6x6, KamAZ-5350, fuel tanker (explodes big and fast) |
| `apc` | `btr`, `bmp`, `mtlb` | BTR-80-style 8x8 (`wheels`, thin armour), BMP-2-style tracked IFV, MT-LB-style light carrier (no turret) |
| `tank` | `t72`, `t80`, `t90` | T-72 (autoloader, turret often blows off), T-80 (gas turbine, quicker), T-90 (composite + reactive armour, wider hull) |

The first variant of each kind is its default.

## SimEvent (one-shot)

Every event has `{ type, time }` plus:

| type               | extra fields | meaning |
|--------------------|--------------|---------|
| `armed`            | –            | motors started |
| `disarmed`         | –            | motors stopped |
| `collision`        | `position, normal, impactSpeed` | the drone bumped something but survived |
| `crash`            | `position, impactSpeed, cause?: 'wire' \| 'shot'` | the drone broke (`cause: 'wire'` = tangled in a telegraph cable, `'shot'` = second hit from small arms) |
| `drone_hit`        | `cause: 'bullet' \| 'thrown', position, hits` | a round or a thrown thing hit the drone (first one only knocks it) |
| `reset`            | –            | drone respawned; visuals should clear trails, debris, etc. |
| `explosion`        | see below | something blew up |
| `drone_lost`       | `reason: 'detonated'`, `respawnIn` (s) | the drone is gone; `link.lost` is true (video feed is static) until the `reset` that follows |
| `hit`              | `entityId, position, damage, source: 'blast' \| 'fragments' \| 'jet', localPosition, localNormal, penetrated, component?, bodyPart?` | a target was hit. `localPosition` / `localNormal` are on the hull (or body) surface in its local frame: the jet's entry point, or the nearest point to a blast: leave a hole or scorch mark there. `penetrated`: the jet got through the armour. `component`: the part it damaged (vehicles). `bodyPart`: 'head' \| 'torso' \| 'armL' \| 'armR' \| 'legL' \| 'legR' (infantry). `damage` = change in `health` |
| `component_damaged`| `entityId, component, state: 'damaged' \| 'destroyed'` | a vehicle part got worse (thrown track, engine smoke, jammed turret, bent gun...) |
| `crew_hit`         | `entityId, role, state: 'wounded' \| 'dead'` | a crewman was hurt or killed inside a vehicle |
| `crew_bailout`     | `entityId, count` | the crew are climbing out (hatches open); they appear as new infantry entities |
| `entity_disabled`  | `entityId, kind: 'mobility' \| 'firepower' \| 'mobility+firepower' \| 'crew'` | a vehicle was knocked out without being destroyed |
| `entity_condition` | `entityId, condition: 'wounded' \| 'crawling' \| 'down' \| 'dead'` | an infantryman's condition changed |
| `entity_spawned`   | `entityId, kind, variant, position, fromVehicle?` | a new entity appeared mid-game (bailing crew) |
| `entity_destroyed` | `entityId, kind, position, cause: 'blast' \| 'fragments' \| 'jet' \| 'cookoff' \| 'fire' \| 'bleedout'` | a vehicle became a wreck (cook-off or burned out) or an infantryman died; it stays in `state.entities` |
| `targets_reset`    | –            | all enemies respawned at their start (ids unchanged): clear wrecks, fires and corpses |
| `entity_alerted`   | `entityId, position` | a unit noticed the drone (visuals may play a shout / turn head); optional to use |
| `link_lost` / `link_restored` | – | signal fell below 0.08 / recovered (not sent for the detonation cut, see `drone_lost`) |
| `mission`          | `id, phase: 'intro' \| 'active' \| 'complete', title` | campaign mission started / objective live / all targets dealt with |
| `mission_line`     | `speaker, text, lineId, radio?` | the other soldier says something (`radio`: a bearing call while you fly) |
| `entity_shot`      | `entityId, from:[x,y,z], to:[x,y,z], hit` | a panicked soldier fires a round at the drone (muzzle flash + tracer) |
| `entity_throw`     | `entityId, item: 'helmet' \| 'rifle', position, velocity` | he throws it at the drone: it flies ballistically from there |
| `mode`             | `mode: 'foot' \| 'drone'` | goggles on / off (campaign). After a detonation the next drone is put by the mast and you are back on foot |

`explosion` fields:

```js
{
  type: 'explosion', time,
  position: [x,y,z],       // centre of the blast
  normal: [x,y,z],         // surface normal it went off against ([0,1,0] in the air)
  surface: 'ground' | 'building' | 'tree' | 'prop' | 'entity' | 'air',
  objectId: string | null, // Level object id or entity id it hit, if any
  kind: 'warhead' | 'vehicle' | 'ammo',   // vehicle = fuel fire / ammo cook-off from a destroyed vehicle (smaller, delayed)
  chargeKg: number,        // TNT equivalent: drives fireball / smoke / crater size (warhead ≈ 0.3–0.7)
  radius: number,          // lethal blast radius, m
  fragmentRadius: number,  // how far fragments fly, m (0 for none)
  shaped: boolean,         // HEAT shaped charge: jet goes along `direction`
  direction: [x,y,z],      // drone's travel direction at detonation (unit)
  turretToss?: boolean,    // cook-off of an autoloader tank (t72 / t80): the turret may fly off the hull
}
```

Suggested visuals: fireball and dust scaled by `chargeKg`, a scorch / small crater
when `surface === 'ground'`, a scorch decal on buildings, fragment sparks out to
`fragmentRadius`.

## Game loop (`src/main.js`)

1. `input.poll()` → `Controls`
2. sim steps at a fixed 240 Hz using an accumulator (max 0.1 s catch-up)
3. `visuals.update(sim.state, sim.drainEvents(), dt)`

## Controls (input → sim)

```js
Controls = {
  throttle: 0..1, yaw: -1..1, pitch: -1..1, roll: -1..1, // pitch +1 = stick forward (nose down), roll +1 = right, yaw +1 = right
  arm, reset, toggleMode, pause, fire, resetTargets,        // edge-triggered booleans (true for one poll); fire = detonate
  interact, goggles,                                        // on foot: either puts the goggles on (at the table); flying: goggles takes them off
  moveX, moveZ: -1..1, lookX, lookY: radians this poll, sprint: boolean,   // on foot (moveZ +1 = forward, lookX + = turn right)
}
```

Default bindings live in `src/input/` and are listed in the README.
